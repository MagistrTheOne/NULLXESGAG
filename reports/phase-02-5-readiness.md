## Исправления и подготовленные функции

- ЦБ: заменён ошибочный GET на SOAP 1.1 POST `KeyRateXML`, добавлена обработка SOAP-обёртки, ISO/даты `DD.MM.YYYY`, проценты, пустой и повторяющийся набор, HTTP 429 и тайм-аут. Наблюдения доступны только консервативно с конца даты действия; точный момент первоначальной публикации ЦБ не выдаёт в контракте этой операции.
- MOEX ISS: проверяются заявленные единицы, схема свечей, даты в запрошенном диапазоне, порядок/дубли страниц, границы и повторяемость пагинации, HTTP-ошибки, rate limit и тайм-аут. Запрос использует явный размер страницы и сохраняет выбранные engine/market/board. Цена облигации остаётся `provider_close_price`: валюта и котировочная конвенция требуют проверки метаданных инструмента.
- FRED/ALFRED: проверяются `count`, `offset`, согласованность страниц, пропуски и повторы дат. Добавлен `historical_vintages()` с ALFRED `vintage_dates`, snapshot запросами `realtime_start`/`realtime_end`, лимитами числа запросов и vintages, интервалом между запросами и явной ошибкой при исчерпании лимита. Значения `.` сохраняются как provider-missing, а не подменяются. Доступность снимка консервативно привязана к концу vintage-даты.
- Общий HTTP-клиент возвращает диагностическую категорию, HTTP status и Retry-After для 429, без скрытого бесконечного retry.
- Backtesting: добавлено сопоставление календарного горизонта 7/30/90 дней с первой фактической биржевой сессией не раньше целевой даты; добавлен origin-specific многогоризонтный walk-forward, фильтр `available_at`, отдельное сопоставление с известным календарём решений ЦБ и проверка заявленной регулярной частоты макроряда.
- Эконометрика: SARIMAX проверяет историю и ADF стационарность, факт сходимости, конечность параметров и границы интервала. GARCH проверяет сходимость, конечность параметров, стационарность `alpha + beta` и дисперсию. Ошибки подгонки возвращают `ModelOutcome` с диагностическим статусом и без числового прогноза.
- Риск: Historical VaR/ES теперь требует не менее 20 конечных наблюдений и проверяет согласованность хвостовых оценок. Monte Carlo сохраняет явное IID Gaussian log-return предположение.
- GEO-RISK/Qwen: добавлены статусы `CONFIRMED_EVENT`, `UNVERIFIED_REPORT`, `ANALYST_ASSUMPTION`; подтверждённое событие требует человеческой проверки. Qwen сверяет HTTPS URL с исходной ссылкой, цитаты — с исходным текстом, даты публикации — с timezone; текст резюме ограничен дословными цитатами. Извлечённое событие всегда остаётся `UNVERIFIED_REPORT`; LLM extraction confidence не используется как вероятность сценария. События без точного timezone-aware publication timestamp не попадают в point-in-time выборку.
- Добавлены чистые тест-кейсы для реальных торговых календарей, календаря заседаний, недостаточной истории, перекрывающихся горизонтов, ревизий макроданных, утечки публикации и неверной частоты рядов. Они написаны, но не исполнялись.
- Создан отдельный `notebooks/colab_acceptance.ipynb`: 14 последовательных acceptance-гейтов (включая явный Drive mount) с диагностикой PASS/FAIL/SKIPPED, без заготовленных результатов. Pytest не устанавливается; если он отсутствует в Colab runtime, тестовый gate остаётся SKIPPED. Qwen модель не загружается автоматически: задаются `QWEN_GGUF_PATH`, исходный документ и URL.

## Статический аудит архитектуры

Код разделён на ingestion, quant, forecasting, storage и intelligence. Адаптеры возвращают общий `Observation`; ALFRED версии сохраняют vintage и input-data version. Backtest принимает явно переданный календарь сессий и не оценивает будущий target при формировании training window. Количество реальных наблюдений, полнота лицензированного ряда, доступность API, схождение моделей и качество вне выборки здесь не измерялись.

Существенная граница: `walk_forward_calendar_horizon` разрешает целевой торговый день по переданному индексу сессий. Этот индекс должен покрывать каждый origin и будущие target-даты без скрытого восстановления отсутствующих сессий. Для моделирования ставки календарь заседаний регулятора также передаётся источником и должен быть известен на момент соответствующего origin. Исторические решения нельзя подменять будущим расписанием.

## Требования к данным и ограничения API

- MOEX ряд должен использовать корректные secid, engine, market, board, интервал и единицы инструмента. Исторические/биржевые данные и их использование могут требовать подписки или отдельного разрешения; код не определяет лицензионные права.
- MOEX candle-ответ сам по себе не содержит универсальную валютную метку для всех инструментов. `provider_close_price` нельзя трактовать как RUB без instrument metadata.
- Для FRED/ALFRED нужен `FRED_API_KEY` в Colab Secrets. Документированный API использует пагинацию `limit`/`offset`; vintagedates возвращает даты, когда ряд менялся, а не неизменённые daily snapshots. Исторический режим ограничивается `max_requests` и `max_vintages`; слишком маленький бюджет явно завершится ошибкой, не частичными незамеченными данными.
- Для каждого макроряда требуются документированные единицы, частота, сезонная корректировка и правило трансформации `units`. Значение `units` в FRED — трансформация ряда, не физическая единица наблюдения.
- Для CBR KeyRateXML документация описывает SOAP параметры и обёртку, но время публикации каждого исторического значения в ответе не подтверждено. Точность XML payload и имена полей должны быть подтверждены acceptance-запуском.
- HTTP 429 сохраняет Retry-After. Код не делает автоматический retry/backoff, чтобы не скрывать лимиты и не выполнять неограниченные запросы.

## Colab readiness and remaining risks

Notebook готов как последовательность запуска и отчётности, но acceptance не прошёл. До запуска нужно поместить проверенную копию репозитория в указанный Google Drive каталог, выполнить Colab Drive authorization, добавить `FRED_API_KEY` как Colab Secret, проверить лицензию MOEX, подготовить актуальный календарь сессий/решений, при необходимости установить pytest отдельно по решению владельца runtime и вручную указать путь к официальной GGUF-модели. Модель и данные должны загружаться только внутри Colab.

Нерешённые риски: CBR XML payload требует подтверждения на реальном ответе; для исторических рыночных цен не получены provider publication/vintage timestamps; требования MOEX по доступу/лицензированию не проверяются программно; реальные торговые и decision calendars пока не подключены к notebook acceptance; сценарные вероятности и GEO-RISK чувствительности не калибровались; стрессовые сдвиги не доказывают причинный эффект; CAPM/волатильность/risk outputs ещё не получили полноценные sample-size/stability guards во всех публичных функциях; отсутствуют реальные backtest метрики и прогнозные coverage результаты.

Финальный статус должен оставаться **UNVERIFIED** до успешного выполнения реальных ingestion, storage, PIT backtests, vintage checks и CPU Qwen этапов в Colab с сохранённым acceptance report. Даже успешный запуск сам по себе не является доказательством прогностического преимущества или разрешением на торговлю.
